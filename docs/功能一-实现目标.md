### 打星定义（使用意图三档 · 取代旧 3/4/5）
- **★1**：存着，以后可能用（素材库候选 / 长期留存）
- **★2**：今天会用，但不作重点（本期辅助素材）
- **★3**：爆点·核心，单独围绕做个话题（主选题）
- **无星**：**不记录**——feed 看过即弃，不持久化，随当天 feed 清理消失。

### 全文抓取生命周期
1. feed 卡片默认只有 标题+链接；用户**点开 = 跳转原链接**自己看。
2. 看完**回来打星（★1/2/3）→ 才触发抓全文并落盘保存**。
3. **取消星 → 删除已抓全文**（回到只剩标题+链接，下一轮 GC 清）。
4. **正在抓时取消星 → 中止抓取任务并删除**半成品。

## 0. 范围与不做项

**做（MVP）**：
- 监控源管理（增/删/列，加源时**试抓校验**）
- 定时抓取（launchd + crawler，本地）→ 产出 feed
- feed 信息流页面（独立页 `收集.html`）：标题+链接、按热度/时间排
- **人工打星**（★1/2/3 使用意图，见上「决策锁定」）
- **惰性全文抓取**：打星即触发抓全文；取消星即删全文
- **留存**：无星不持久化（随当天 feed 清）；有星落盘保存
- 上传文件 + 粘贴文本两种即时来源（复用现有 `/collect`）

- 配额/付费、多租户、云端（本地优先，单用户）
- **热度排序**（D4：先完全不管）
- **HTML 列表页启发式发现**（D3：先只吃结构化源）
- 发布后运营数据追踪
- MP3/MP4 大文件

## 1. 关键技术结论（动手前必须知道）

| 能力 | 现状 | 结论 |
|---|---|---|
| 单 URL→全文 | 编辑部 `采集.fetch_url` 已有（含 playwright 兜底） | **复用**：惰性全文抓取直接调它 |

### 1.1 监控源「发现新条目」策略（MVP，D3 已修订：HTML 主路）
发现顺序（`crawler.discover()` 内部自动判别）：
1. **先试结构化源**：源 URL 能被解析为 RSS/Atom（`<item>/<entry>`）或 sitemap（`<url><loc>`）→ 直接出条目清单（碰上就用，最干净）。
2. **回落 HTML 列表解析（主路）**：提取页面内 `<a href>`+锚文本，按「**href 含日期路径**（`/20\d{6}/` 或 `/20\d\d-\d\d/`）或像文章详情页 + **锚文本≥8 字**」启发式筛出文章链接，相对链接 urljoin 成绝对、同域、去重。
   - 实测 news.cn `/info/xhsz/`、`/info/gxqy/` 均精确命中目标文章。
3. **加源时试抓**：跑一次 discover，**抓到 ≥1 条才允许添加**；否则告知「该页未能解析出文章链接（换一个栏目列表页/详情页规律更清晰的源）」。

### 1.2 增量去重
- 每个源一个 `snapshot`（已见 URL 集合）。新一轮只处理 `url not in snapshot` 的条目。
- 跨源去重**不强制**（按用户口径，重复是用户自己的事）。

## 2. 数据结构（D5：SQLite 为主，沿用 claude进化史 范式）

DB 文件：`收集/data/collect.db`（`sqlite3` 标准库）。全文落盘：`收集/fulltext/{feed_id}.json`。

```sql
-- 监控源（全局/主体级，跨笔记本共享）
CREATE TABLE source (
  id        TEXT PRIMARY KEY,   -- mon_xxx
  url       TEXT UNIQUE,        -- 结构化源地址（RSS/sitemap）
  title     TEXT,
  kind      TEXT,               -- rss | sitemap | registry
  freq      TEXT,               -- daily | hourly
  grp       TEXT,               -- 分组，如「政策类」
  enabled   INTEGER DEFAULT 1,
  last_run  TEXT
);
-- 已见 URL 快照（增量去重，每源一组）
CREATE TABLE seen (
  source_id TEXT, url TEXT,
  PRIMARY KEY(source_id, url)
);
-- feed 条目
CREATE TABLE feed (
  id         TEXT PRIMARY KEY,  -- f_xxx
  source_id  TEXT,
  title      TEXT,
  url        TEXT,
  fetched_at TEXT,
  star       INTEGER DEFAULT 0, -- 0 无星 / 1 / 2 / 3（使用意图，见决策锁定）
  fulltext   INTEGER DEFAULT 0, -- 是否已抓全文落盘
  pinned_to  TEXT               -- 挂到某工作流则豁免 GC（埋雷豁免）
);
CREATE INDEX idx_feed_star ON feed(star);
CREATE INDEX idx_feed_fetched ON feed(fetched_at);
```

### 2.x 小配置（JSON：`收集/config.json`）
```json
{"gc":{"keepUnstarredHours":24}}   // 无星 feed 保留时长；有星一律落盘留存
```

> 留存逻辑由打星驱动（见「全文抓取生命周期」），不再用旧的「按星几天」旋钮。

## 4. 抓取调度（本地）
- `收集/crawler.py`：复用「锁(PID) + 冷却 + 快照」；遍历到期源 → 发现新条目 → 写 feed.json。
- `收集/com.bijitai.crawl.plist`（launchd）：每小时唤醒一次，crawler 内部按各源 freq 判断是否真跑。
- 安装脚本 `收集/install-crawl.sh`：`launchctl load` plist。

## 5. 前端独立页 `收集.html`
- 顶部：监控源管理条（加源/列表/开关/分组）。
- 主体：**feed 信息流**——卡片含 标题·来源·时间·链接(点击=外开原文)·**★1/2/3 打星**（打星即触发抓全文）。
- 排序：**时间倒序**（D4 热度先不做）。筛选：按源 / 按星档。
- 已打星条目可单独看一栏（★3 主选题 / ★2 本期 / ★1 候选）。
- 设置抽屉：无星 feed 保留时长（默认 24h）。
- 复用现有 `server.py`；与 `index.html` 各自独立可单跑，后续并入零成本。

## 6. 验收（怎么算这一步完成）
1. 能加一个 RSS/sitemap 源，试抓校验通过（非结构化源被当场拒绝并给出可读原因）。
2. 手动 `/mon-run` 后 feed 出现多条标题+链接，按时间倒序。
3. 打 ★ 某条 → 自动抓回全文落盘（`fulltext=1`）；取消 ★ → 全文被删。
4. GC 跑一遍：无星 feed 满 24h 被清；有星条目保留。
5. 增量正确：再跑一次 `/mon-run`，已见 URL 不重复进 feed。

## 7. 埋雷清单（实现时勿忘）
- 标星抓全文且 `pinnedTo` 的条目，GC **必须豁免**。
- 试抓失败要给**可读中文原因**（沿用 `_clean_traceback` 风格）。
- crawler 与 server 同时读写 SQLite → 用 `sqlite3` 自带事务/WAL，避免 feed 写冲突。
- 取消星要可靠中止「正在进行」的全文抓取任务并删半成品（任务表/标志位）。

## 9. 验收反馈待改清单（2026-06-04，记完统一改）

1. **抓取时间设置**：freq=每天 时支持「每天抓几次、在几点」（UI+调度都要）；每小时模式保持现状。（非重点）
2. **资讯流自动更新**：feed 按调度自动流入（开 launchd 后页面定时刷新/自动加载），「立即抓取」只是手动补充，不应是唯一入口。
3. **卡片日期 = 报道日期**：解析文章发布日期来显示（news.cn 可直接从 URL `/YYYYMMDD/` 提取），不是 fetched_at。
4. **时间窗口过滤**：增量只收「上次抓取之后发布的」；**首抓只回溯 7 天**。当前 seen 去重导致首抓把整页旧闻（4月）全收了——不合理。
5. **简易第二页面（打星文章库）**：打星保存的全文要有去处可见——先建一个简易页：已打星文章列表，点开可读全文（txt/markdown 渲染）。完整功能二后续替换。
6. **取消星要显式**：现「再点同星=归零」太隐蔽，加明确的「✕ 取消/零星」入口。
7. **清理无星=立即清**：手动点「🧹」应立即清掉**所有**无星（当前因 24h 门槛今天刚抓的清不掉，像没反应）；24h 规则只留给自动 GC。
8. **底部「确认」按钮**：打星完成后一键确认 → 跳转简易第二页面（第二环节入口）。
9. **新旧分明 + 凌晨自动清理**：每晚 **2:00 自动清理「已读且无星」**（不是清全部——一天抓多次会有未读，未读保留）。feed 区分 未读/已读 态。
10. **「已读」判定机制（已拍板）**：**B 主判定——卡片入屏停留 ≥3 秒 = 已读**（一屏多卡，扫一眼约 3s）；**A 兜底——点开链接必算已读**。
11. ~~键盘流快捷键~~ **不做**：页面将来要适配手机端，以点击打星为主。

### 监控源平台路线（2026-06-04 记，当日多轮迭代后）
- **已支持**：网页栏目/列表页（HTML，主路）、**政府部委站（大汉 jpaas CMS，自动调 unit 接口）**、RSS/Atom、sitemap（**含 Google News 扩展** `news:title`/`publication_date`，slug 自动美化）。HTML 解析认「链接旁日期」。URL 日期识别 5 种模式（`/20260602/`、`/2026-06-02`、`/202606/03`、`t20260603_`、`/2026/0603/`）。
- **后续接入**：公众号作者（需搜狗微信等通道）、微博、B站 UP。UI 已标注。

### 🤖 监控源接入助手（agent，2026-06-04 下午落地）
- **触发**：加源常规试抓失败（解析不出 / 抓取报错均触发）→ 右下角小窗自动唤起。
- **能力 1（配方分析）**：抓页面 HTML → 经本机 claude CLI 产出「抓取配方」JSON → 执行验证 ≥2 条才收 → 自动加源（kind=agent）。配方存 `source.recipe`，日常抓取按配方执行。
- **能力 2（公开通道探测）**：页面直连被反爬拒绝（401 等）→ 自动探测 11 种「给搜索引擎留的公开通道」（Arc CMS outboundfeeds / news-sitemap.xml / rss 等）→ 命中后**按原 URL 栏目路径过滤**（feed 配方 + url_contains），栏目条目太少则退全站。实战：路透 Datadome 反爬 → news-sitemap 通道 → 栏目过滤 → 自动接入。
- **小窗交互**：实时滚动日志；卡住转 waiting 等用户递线索（say 续跑）；会话严格限定加源任务；页面启动自动接上最近活跃任务（`latest`）；外部工作者（终端 Claude）可经 `log` 动作实时报工。
- **配方格式**（`crawler.run_recipe`）：`extract=regex|json|feed`；regex 用命名组 `(?P<title>)(?P<url>)(?P<date>)`；json 走 `list_path` 点路径（取到 HTML 再 `then_pattern`）；feed 走结构化解析 + `url_contains` 栏目过滤。
- **已知限制**：强反爬站（路透等）文章页打星抓全文会失败（⚠ 显示），点链接浏览器看原文不受影响。
