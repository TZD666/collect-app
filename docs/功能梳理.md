## 0. 核心定位（用户主导定调）

### 0.1 本质
「笔记台」**本质是一个 AI 产品**，不是工具集。
为**不同主体**（一家公司 / 一个个人 / 一个大集团）提供一套**快速、风格化的「编辑部」发布流程**——产出要符合该主体**自己的风格与偏好**（风格化是核心卖点，不是通用模板）。
当前覆盖形态：**仅文案**（后续会扩展到视频 / 图文 / 播客等其他形态）。

### 0.2 终极形态：一个大 Agent
- 1–7 全是**可被调用的工具**（手脚）。
- 8–9 才是**核心**：一个**个人 AI 的沉淀**（每个主体专属的偏好/记忆内核，大脑）。
- 对外提供 **AI agent 调用接口**——整个产品是一个**多 agent 组合的大 agent**。
- 学到的偏好能**固化成「调用工具的模板」**，下次直接复用。
- **终极体验三词：快 · 符合心意 · 方便**——用户丢一份资料、说个思路，就能极快发出对味的文案。
  之所以能快，是因为 8–9 已经替他把风格/偏向/知识/工具顺序都预先选好了。

### 0.3 两条性质不同的链
| | 1–7 生产流水线 | 8–9 学习回路 |
|---|---|---|
| 是什么 | **一个完整产品**：把「社媒运营 / 某行业」的理解工程化落地（domain know-how） | **产品的迭代方式 / 一种通用能力**：用 AI 贴合用户偏好的管理机制 |
| 可见性 | 用户看得见 | 偏黑箱、自动、隐蔽 |
| 可复用性 | 绑定本产品 | **可单独拎出、套到其他产品上**（价值外溢） |
| 定位 | 肌肉 | 大脑 · **真护城河** |
| 工程阶段 | 现有代码已走通大半 | 从 0 开始 |

### 0.4 一等公民：风格 × 偏向（两个独立维度）
- **风格（Style）= 怎么说**：语气 / 图片风格 / 排版风格（多种多样，已有 kira、李一舟 lyz…可插拔、可定制、可替换）。
- **偏向（Orientation）= 为谁说·为何说**：政策解读 / 产品宣传 / 商业 / 科普……（由**目的**决定）。
- 两者**相互影响但本质是两个轴**，不可混为一谈。
- **每个模块都可定制化、可替换**（生成文案处，风格和偏向都可选）。
- **风格可反向沉淀**：用户常说不清自己要什么风格，但看到某个 up/博主对味 → 可把那人的内容/链接丢进来，**反向分析、提炼成可调用的风格**，存进风格库。
  （这与功能 9「从审批人改稿学偏好」是**同一能力的两个入口**。）

### 0.5 与 NotebookLM 的关系：借壳，不对标
- 抄了它的三栏页面结构（前端壳），后端内核完全不同。
- 它**做得更广**（卡片/思维导图/视频/播客，因为是通用工具）；我们**链路更长、垂直**（风格化发布 + 回流学习）。
- 功能 6–9 在 NotebookLM 里**没有对应 UI 可抄**，需自己原创。

### 0.6 两个长期资产（一个主体的完整画像）
- **知识库** = 这个主体「知道什么」（公司资料 + 已发文章…）
- **风格/偏向档案** = 这个主体「怎么表达」
- 8–9 学到的一切，最终都落进这两个资产。

### 0.7 模块化架构观：独立 App + 管家 AI（2026-06-04 第二场，用户定调）

> 转向：原计划「把 1–7 拉通全建出来再填功能」→ 改为「**每个模块做成一个独立 App，各配一个专属 AI（管家）**」。

- **与 NotebookLM 的差异化核心 = 每个模块的 AI**：管家负责该模块内的全部知识管理；能**不改基础代码**、通过与用户的简单交流去调整/实现模块内功能（用户提需求 → 管家自己消化落地）。现有🤖接入助手（claude CLI 产抓取配方，配方进库、代码不动）就是这个思路在功能一的雏形。
- **每个模块 = 独立 App**：自己的数据库（如收集模块：追踪源 / 抓取时间 / 打星文章）+ 自己的 UI + 自己的管家 AI，单独可用。
- **模块间靠数据交互衔接**：各自数据库 + **共通数据库**；上游把产物传给下游（如收集 → 把高分文章全文/链接传给总结）。
- **管家 → 大脑，两阶段**：
  1. 先让各管家把自己模块的事做好（1–7 逐个成型）；
  2. 1–7 全拉通后，再建一个**大脑**：分别了解每个管家在做的事 + 各自核心资料，沉淀为总的**行为飞轮 / 数据飞轮**（即 8–9 的落地形态）。
- **App 形态（重要拍板，回答 2.6 架构岔路）**：现在的 HTML 单文件形式「有点儿戏」，必须**正规化**——
  - 能**单独部署在服务器上**运行；
  - 有自己的用户界面，**不同用户登录看到不同内容**；
  - 至少具备：**数据库 + 模块间权限界定（工作流程）+ 身份层**；
  - 最终目标：不同用户在不同端（设备）直接登录即用；**一开始做成手机也能登录使用的网页**即可。
- **改造约束**：收集模块已沉淀的基础代码**不推翻**，在其上做更规范、更工程化的改造。

## 2. 功能一：收集资料（已谈透 🟢）

### 2.1 三种来源
1. **监控抓取（定期）**——参考此前的 Claude Code 跟踪器（「锁+冷却+快照」模式，抓官网/NPM/新闻更新）。定期抓监控源的新内容。对应现有 `meta.monitors[]`（原 Phase 2）。
2. **用户上传**——仿 NotebookLM：PDF / txt / 文本类（可带图）。**一期不做 MP3/MP4 等大文件**。
3. **核心知识库（沉淀型 · 长期记忆）**——见 2.5。

### 2.2 「筛选」归功能一（A 方案，已拍板）
- 理由：实时抓取≈**热点新闻**，蹭热度**窗口≈3 天**，超了就是炒冷饭 → 必须当场快速决断，不能拖到功能二。
- 形态：**feed 信息流**（不像 Claude 跟踪器那样钉死成固定可视化报告）。用户每天打开，第一眼看到「今天监控源抓到了什么新东西」。

### 2.3 人工打星（前期筛选机制）
- 参考：专业设没运营者**订阅海量来源**，每天早起到上班这段就在**快速扫高热来源、打分（五星/四星/三星）**。
- 前期我们还不懂用户数据偏好时，**先给「打星」功能**：用户快速扫 feed、打星、勾定哪些进入功能二。
- **打星本身 = 8–9 的训练燃料**：前期人工打星，攒够后 8–9 反过来自动预排序，人工逐渐退化为「确认/微调」。

### 2.4 抓取深度（惰性 lazy，分两级）+ 留存
- **默认只抓「标题 + 链接」** → 进 feed 供扫、点链接自己看原文。
- **用户标星 / 要进功能二的那一刻 → 才真正抓全文。**（重要的用户本就会点链接看，看了是水文就不标星。全文抓取按需触发，省抓取量/存储。）
- **收集池 = 临时缓存层，不是正式库**：「从源筛 → 重要的抓全文进下一环 → 不重要的当天清」。正式入哪个库、库怎么分，**到时候再定，现在不锁死**。
- **留存分级（可调旋钮）**：未标星→当天删；低星(如三星)→留 3 天；标星/心急→永久保留（存链接）。
- **原则：热度由用户自己标、自己追踪，他就承担标记义务。**
- ⚠️ **埋雷豁免**：用户标星抓了全文、但还没跑完功能二就关软件 → 这批全文要挂到具体工作流上，**豁免「当天清」**，不能误删。

### 2.5 核心知识库（硬骨头 · 先搁置，边用边啃）
- **沉淀型、反复用、半隐性**：一次沉淀、长期自动复用、用户不必每次重新指定（区别于监控/上传的临时、可见、每次重指定）。
- **层级比笔记本高**：跨笔记本、属于整个主体的底座。
- **沉淀来源多种**：已发文章（沉淀文风/内容）、公司资料（背景/产品/事实底座）、交流中暴露的偏好。
  → 前两者喂「知识库」，后者喂「风格/偏向档案」。
- **动态更替**：库里资料有核心/边缘之分，随时间更替；「哪些真被用/被偏好」本身是信号，**与 8–9 连体**。
- **分层 / 保密分级（核心且麻烦，安全红线）**：用户**讨论**时尽量多补信息（含敏感内部），但**对外发**时不想全公开。
  → 每条知识打**「仅内部参考 / 可对外输出」**标签：仅内部的只帮 AI 理解背景、不落成品；只有可对外的能进正文。**边界没划好会泄密。**
- **策略（用户拍板）**：先把功能跑起来，知识库这块硬骨头**边用边改边进化**，靠自己用 + 用户用暴露「最讨厌的地方」再迭代，不提前过度设计。

### 2.6 商业约束：配额 / 付费（决定架构走向）
- 设没运营**自己清楚该盯哪些源**（如做数字化制造盯工信部，且工信部低频、不天天发）。我们提供的是**方便的监听渠道**，不替他想订阅什么。
- **实时监听吃服务器** → 不能无限免费：**免费档限量**（每天抓 N 篇 / 监听 M 个源 / 频率档），更多要**付费**。
- 副作用：**配额逼用户自己把最重要的源筛出来**（省钱动机天然帮我们做源优先级）。
- 去重**不强制**（按抓取量收费，重复是用户自己的事，浪费额度自担）；可给「去重按钮」，加不加无所谓。
- ✅ **架构岔路（2026-06-04 已定）**：走**云服务**——可部署服务器、多用户登录、手机网页可用（详见 0.7）。「127.0.0.1 单机」是过渡形态。

### 2.7 抓取健壮性
- **加监控源时先跑一次试抓**：源反爬/抓不到 → 当场告诉用户「此源不可监听」，不让他加。
- 试抓通过、后来网站改版/上反爬 → 怎么处理（静默停 vs 提醒）尚未定。

### 2.8 功能一→功能二的接口
- 传过去的是**标星后抓的全文**（标题+链接为主的进不去）。

## 4. 待澄清清单（开发前要拍的硬决策）
